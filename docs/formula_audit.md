## 尚未關閉的證據缺口

- Phase 0：Astropy GCRS 輸出標成 `GCRF` 的全時段 frame 誤差預算尚無；DNSAPOD loader 的 deg 內部介面與 rad 規則衝突。使用實際 `ap` 的 M0 原生 MSIS 只有明列的來源分鐘抽查，不能推成全時段數值庫驗證；quiet MSIS 已額外在 Phase 3 與 Phase 7 校準段由原生 ZIP 重算，但仍依同一 pymsis；現行 `ap_values` 與 pymsis 的當前格／當日 daily ap 慣例不同，見 P0-A。
